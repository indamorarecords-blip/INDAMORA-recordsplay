NE PAS RECONSTRUIRE INDAMORA PLAY.

Cette modification doit être réalisée sur LES DEUX INTERFACES :

1. 🌐 le site web https://indamoraplay.com/
2. 📱 l’application / PWA INDAMORA PLAY

IMPORTANT :
Le site et l’application doivent utiliser les mêmes données, le même backend, les mêmes comptes, les mêmes profils et les mêmes permissions ADMINISTRATEUR.

Il ne faut surtout pas créer deux systèmes indépendants.

OBJECTIF

Dans le profil / centre ADMINISTRATEUR, je dois pouvoir gérer depuis le site ET depuis l’application :

* les personnes inscrites
* les comptes SIGN IN / SIGN UP
* les profils INDAMORA créés
* les profils artistes
* les profils professionnels
* les activités sélectionnées
* les profils en attente de validation
* les profils validés
* les profils publiés dans RÉPERTOIRE
* les œuvres associées aux profils

L’administrateur doit retrouver les mêmes informations et les mêmes actions sur le web et sur l’application.

⸻

1. ADMINISTRATEUR — UTILISATEURS

Ajouter dans le centre ADMINISTRATEUR existant une rubrique :

👥 UTILISATEURS / INSCRIPTIONS

L’administrateur doit pouvoir voir les comptes réellement inscrits sur INDAMORA PLAY.

Afficher lorsque disponible :

* Prénom
* Nom
* Email
* Date d’inscription
* Statut du compte
* Vérification de l’email
* Profil INDAMORA créé ou non
* Activité(s)
* Statut du profil
* Dernière activité si cette donnée existe déjà

Ces données doivent être visibles uniquement par l’administrateur autorisé.

⸻

2. SIGN IN / SIGN UP

Conserver le système d’authentification existant.

L’administration doit permettre de distinguer :

* compte créé
* compte vérifié
* compte avec profil INDAMORA
* compte sans profil INDAMORA
* profil en attente
* profil validé
* profil publié

Ne pas créer un deuxième système d’authentification.

5. VALIDATION

L’administrateur doit pouvoir gérer le statut lorsque le système existant le permet :

* EN ATTENTE
* VALIDÉ
* REFUSÉ / À CORRIGER
* PUBLIÉ
* NON PUBLIÉ

Une validation effectuée depuis le site doit immédiatement être visible dans l’application.

Une validation effectuée depuis l’application doit immédiatement être visible sur le site.

Il ne doit pas y avoir deux états différents.

10. SÉCURITÉ

CRITIQUE.

Les données administratives doivent être protégées côté serveur.

Ne pas simplement cacher les boutons sur le frontend.

Tester les permissions serveur.

TEST

Utilisateur normal → ADMIN refusé

Artiste → ADMIN refusé

Visiteur → ADMIN refusé

Administrateur autorisé → ADMIN accessible

Un utilisateur normal ne doit jamais pouvoir appeler directement une API pour récupérer la liste globale des utilisateurs.
