FONCTIONNEL

==================================================
2. PRIORITÉ N°1 — FINALISER LA SÉPARATION DES ESPACES

La prochaine priorité est de finaliser la séparation réelle :

VISITEUR / USER
ARTISTE
ADMIN

Ne refais pas le système de rôles s’il existe déjà et fonctionne.

Vérifie simplement qu’il est réellement appliqué partout.

Un visiteur doit rester dans l’espace public et son compte.

Un artiste doit accéder à son propre espace artiste.

Un administrateur doit accéder à l’administration.

Les permissions doivent être cohérentes entre :

frontend
backend
base de données
RLS

Si cette partie est déjà réellement fonctionnelle et testée, laisse-la intacte et passe à la suite.

==================================================
3. PRIORITÉ N°2 — PROPRIÉTÉ DES DONNÉES ARTISTE

Vérifie qu’un artiste ne peut manipuler que SES données.

Tester réellement :

* profil ;
* musiques ;
* albums ;
* vidéos/médias ;
* œuvres ;
* statistiques ;
* éventuelles données financières.

Un artiste A ne doit pas pouvoir modifier l’artiste B en changeant simplement un ID ou UUID.

Si cette protection existe déjà et fonctionne :
NE LA REFAIS PAS.

Si elle est incomplète :
corrige uniquement le contrôle manquant.

==================================================
4. PRIORITÉ N°3 — PROTECTION DES API ET FONCTIONS SERVEUR

Inspecte les API et fonctions serveur existantes.

Cherche uniquement les endpoints qui ne possèdent pas encore les vérifications nécessaires.

Pour chaque endpoint sensible :

* utilisateur authentifié ;
* rôle vérifié ;
* propriétaire vérifié lorsque nécessaire ;
* autorisation vérifiée avant lecture/modification/suppression.

Ne modifie pas les endpoints déjà correctement protégés.

Ne crée pas une nouvelle architecture d’API si celle actuelle fonctionne.

==================================================
5. PRIORITÉ N°4 — RLS ET BASE DE DONNÉES

Inspecte les politiques RLS actuellement présentes.

Ne supprime aucune politique fonctionnelle.

Identifie uniquement les tables ou opérations qui restent insuffisamment protégées.

Vérifie notamment les données privées liées :

* utilisateurs ;
* artistes ;
* œuvres ;
* soumissions ;
* statistiques ;
* paiements ;
* revenus ;
* administration.

Corrige uniquement les failles réellement présentes.

Teste ensuite les accès avec différents rôles.

==================================================
6. PRIORITÉ N°5 — ESPACE ARTISTE

Vérifie ce qui manque encore réellement dans l’espace artiste.

L’espace doit, lorsque les fonctions correspondantes existent dans le projet, permettre :

* tableau de bord ;
* profil artiste ;
* œuvres ;
* ajout d’œuvre ;
* musiques ;
* albums ;
* médias ;
* statut de validation ;
* statistiques ;
* notifications ;
* paramètres.

Ne crée pas une nouvelle interface si celle-ci existe déjà.

Complète uniquement les écrans ou fonctions absents.

==================================================
7. PRIORITÉ N°6 — WORKFLOW DE VALIDATION

Vérifie le cycle complet :

ARTISTE
→ soumission
→ EN ATTENTE
→ ADMINISTRATION
→ VALIDATION ou REFUS
→ publication si validée

Vérifie que l’artiste peut voir le statut de SES propres œuvres.

Vérifie que l’administrateur peut gérer les soumissions.

Vérifie qu’une œuvre refusée n’est pas publiée par erreur.

Vérifie qu’un artiste ne peut pas modifier directement le statut de validation.

Si ce workflow fonctionne déjà :
NE LE REFAIS PAS.

==================================================

Vérifie le fonctionnement réel des médias.

Selon ce qui existe déjà :

* upload ;
* stockage ;
* couverture ;
* audio ;
* vidéo ;
* lecture ;
* suppression ;
* association artiste/œuvre ;
* publication après validation.

Ne remplace pas le système de stockage existant s’il fonctionne.

Corrige uniquement les problèmes constatés.

==================================================
9. PRIORITÉ N°8 — RECHERCHE ET CATALOGUE

Vérifie la recherche globale.

Elle doit rechercher, lorsque les données existent :

* artistes ;
* morceaux ;
* albums ;
* vidéos.

Vérifie également les catégories et les filtres.

Ne modifie pas les catégories déjà fonctionnelles.

Ne crée pas de données fictives pour remplir le catalogue.

==================================================
10. PRIORITÉ N°9 — NOTIFICATIONS

Vérifie si le système de notifications existe déjà.

Si oui :
teste-le et conserve-le.

S’il est incomplet :
complète uniquement ce qui manque.

Cas importants :

* œuvre reçue ;
* œuvre validée ;
* œuvre refusée ;
* informations administratives importantes.

==================================================
11. PRIORITÉ N°10 — STATISTIQUES

Vérifie les statistiques existantes.

Séparer clairement :

STATISTIQUES ARTISTE
→ uniquement ses propres données.

STATISTIQUES ADMIN
→ données globales autorisées.

Ne crée pas de faux chiffres.

S’il n’existe pas encore suffisamment de données réelles pour certaines statistiques, afficher un état vide approprié plutôt qu’inventer des chiffres.

==================================================
12. PRIORITÉ N°11 — COMPTE UTILISATEUR

Vérifie que l’utilisateur peut réellement gérer son compte :

* informations personnelles ;
* session ;
* paramètres ;
* abonnement si disponible ;
* historique de dons si disponible.

Un utilisateur ne doit pouvoir modifier que ses propres informations.

==================================================

« Aucun artiste disponible pour le moment. »

« Aucune vidéo disponible pour le moment. »

« Aucune œuvre disponible pour le moment. »
