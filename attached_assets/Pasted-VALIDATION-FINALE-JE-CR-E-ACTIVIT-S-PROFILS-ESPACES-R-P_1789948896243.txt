⚠️ NE MODIFIE PAS LE CODE SANS NÉCESSITÉ

Ne pas :

* refaire l’inscription ;
* modifier Clerk ;

* modifier l’architecture existante inutilement ;
* modifier le design sans nécessité ;
* créer un nouveau système d’authentification ;
* créer de faux comptes ;
* créer de fausses données ;
* modifier le RÉPERTOIRE inutilement ;
* casser les fonctionnalités déjà opérationnelles.

L’objectif est de TESTER, VÉRIFIER ET COMPLÉTER UNIQUEMENT CE QUI MANQUE.

1. PRINCIPE CENTRAL — CHAQUE PROFIL DOIT AVOIR SON ESPACE ADAPTÉ

Une personne qui crée un espace sur INDAMORA PLAY ne doit pas avoir automatiquement la même interface que tous les autres utilisateurs.

L’interface doit être adaptée au profil et aux activités choisies.

👤 VISITEUR / AUDITEUR

Une personne qui crée un espace en tant que :

🎧 Auditeur / visiteur

doit avoir son propre espace visiteur/auditeur.

Elle ne doit pas voir l’interface réservée aux artistes.

Elle ne doit pas voir l’interface ADMIN.

Elle ne doit pas voir :

* gestion des œuvres ;
* dépôt d’œuvres ;
* gestion des médias artistes ;
* modération ;
* gestion des artistes ;
* statistiques globales ;
* données financières globales ;
* outils ADMIN.

Elle doit pouvoir utiliser uniquement les fonctionnalités correspondant à son espace.

⸻

2. ESPACE ARTISTE / TALENT

Une personne qui crée un espace en tant que :

🎤 Artiste
💃 Danseur / danseuse
🎬 Acteur / réalisateur
🎥 Vidéaste
😂 Humoriste
🎧 Podcasteur
📱 Créateur de contenu
⭐ Influenceur
🎙️ Chanteur / chantre
🎚️ Producteur
ou toute autre activité disponible

doit avoir un espace artiste / créateur / professionnel adapté à ses activités.

Cet espace doit être différent de celui d’un simple visiteur/auditeur.

Il peut notamment contenir, selon les activités :

* mon profil ;
* mes activités ;
* ma bio ;
* mes œuvres ;
* mes médias ;
* déposer une œuvre ;
* mes soumissions ;
* statut de mes soumissions ;
* mes statistiques ;
* mes notifications ;
* mes informations professionnelles.

IMPORTANT

Un artiste ne doit pas voir les outils réservés à l’ADMINISTRATEUR.

Il ne doit notamment pas voir :

* utilisateurs globaux ;
* dons globaux ;
* revenus globaux ;
* paiements globaux ;
* événements Stripe ;
* statistiques globales ;
* journal ADMIN ;
* modération globale ;
* gestion globale des artistes ;
* gestion globale du RÉPERTOIRE.

⸻

3. ESPACE ADAPTÉ AUX ACTIVITÉS

Les deux activités choisies doivent pouvoir déterminer les fonctionnalités disponibles dans l’espace.

Exemple :

🎤 Artiste + 🎚️ Producteur

L’espace peut proposer :

* profil artiste ;
* œuvres ;
* dépôt musical ;
* production ;
* médias ;
* statistiques personnelles.

🎥 Vidéaste + 📱 Créateur de contenu

L’espace peut proposer :

* profil ;
* présentation ;
* médias ;
* contenus ;
* portfolio ;
* statistiques personnelles.

💃 Danseur + 🎬 Créateur

L’espace peut proposer :

* profil ;
* présentation ;
* médias ;
* contenus ;
* visibilité dans le RÉPERTOIRE.

📰 Journaliste + 📺 Média

L’espace peut proposer les fonctionnalités correspondant aux activités sélectionnées.

Ne pas créer artificiellement des fonctionnalités qui n’existent pas.

Adapter l’affichage aux fonctionnalités réellement disponibles dans INDAMORA PLAY.

⸻

4. ADMINISTRATEUR

L’ADMINISTRATEUR possède un espace totalement différent.

Il s’agit du CENTRE DE PILOTAGE INDAMORA PLAY.

L’ADMIN ne doit pas avoir la même interface qu’un visiteur.

L’ADMIN ne doit pas avoir la même interface qu’un artiste.

Il doit pouvoir accéder aux outils nécessaires à l’administration globale :

* utilisateurs ;
* artistes ;
* profils ;
* activités ;
* œuvres ;
* médias ;
* RÉPERTOIRE ;
* catégories ;
* modération ;
* presse ;
* statistiques ;
* visites ;
* écoutes ;
* recherches ;
* abonnements ;
* paiements ;
* dons ;
* événements Stripe ;
* journal ADMIN.

⸻

Mettre en place et vérifier une séparation claire :

Cette matrice concerne les droits et interfaces, pas la création de plusieurs comptes.

Une même personne conserve son compte.

⸻

6. SÉCURITÉ — L’INTERFACE NE SUFFIT PAS

Cacher un bouton ne suffit pas.

Les permissions doivent être contrôlées côté serveur/API.

Un visiteur ne doit pas pouvoir devenir artiste simplement en modifiant une URL.

Un artiste ne doit pas pouvoir devenir ADMIN en modifiant le frontend.

Un utilisateur ne doit pas pouvoir appeler directement une route réservée à un autre rôle.

Tester notamment :

* accès direct aux URLs ;
* accès API ;
* modification de paramètres ;
* requêtes manuelles ;
* changement de rôle côté client.

⸻

7. JE CRÉE

Le bouton :

🎨 JE CRÉE

doit permettre à une personne de rejoindre l’écosystème INDAMORA PLAY.

Lorsqu’elle clique sur JE CRÉE, elle choisit son ou ses activités.

⸻

8. MAXIMUM 2 ACTIVITÉS

UNE PERSONNE PEUT CHOISIR MAXIMUM 2 ACTIVITÉS.

Exemples :

✅ Artiste + Producteur

✅ Danseur + Créateur de contenu

✅ Vidéaste + Influenceur

❌ Artiste + Producteur + Vidéaste

Le frontend doit empêcher la troisième sélection.

Le serveur/API doit également refuser une requête contenant trois activités.

⸻

9. BIO

La bio reste libre.

Les activités sélectionnées servent à structurer le profil.

La bio permet de détailler d’autres compétences.

Exemple :

Activités :

🎤 Artiste
🎚️ Producteur

Bio :

« Artiste, producteur, vidéaste et créateur de contenu. »

Cela ne doit pas créer automatiquement une troisième activité structurée.

12. RÉPERTOIRE

Le RÉPERTOIRE reste le cœur d’INDAMORA PLAY.

Les activités doivent permettre de classer et retrouver les profils.

Le RÉPERTOIRE doit pouvoir distinguer notamment :

* artistes ;
* danseurs ;
* producteurs ;
* créateurs ;
* vidéastes ;
* médias ;
* journalistes ;
* structures ;
* partenaires ;
* autres profils disponibles.

Conserver :

* recherche ;
* filtres ;
* catégories ;
* sous-catégories ;
* pays ;
* profils ;
* œuvres.

⸻

13. DONATIONS

Conserver le système de dons existant en production.

Visiteurs et artistes peuvent faire un don.

Ils ne peuvent pas :

* voir le montant global reçu ;
* voir les revenus globaux ;
* accéder au compte Stripe ;
* effectuer un virement ;
* retirer les fonds ;
* gérer les finances de la plateforme.

L’ADMIN dispose des informations nécessaires à la gestion.

⸻

14. ABONNEMENTS

Conserver le système d’abonnement existant.

Les droits doivent être vérifiés côté serveur.

Ne pas refaire Stripe si le système fonctionne déjà.

⸻

15. STATISTIQUES

Les artistes/professionnels voient uniquement leurs propres statistiques lorsque disponibles.

L’ADMIN peut consulter les statistiques globales nécessaires au pilotage.

Ne jamais créer de statistiques fictives.

⸻

16. JOURNAL ADMIN

Les actions administratives importantes doivent être enregistrées :

* validation ;
* rejet ;
* publication ;
* modification ;
* dépublication ;
* suppression ;
* gestion d’un profil ;
* gestion d’une œuvre ;
* gestion d’un média.

Accessible uniquement à l’ADMIN autorisé.

17. TESTS OBLIGATOIRES DES ESPACES

Tester au minimum :

TEST A — VISITEUR

Créer/ouvrir un espace visiteur.

Vérifier que l’interface visiteur s’affiche.

Vérifier que les outils artiste et ADMIN sont absents.

TEST B — ARTISTE

Créer/ouvrir un espace artiste.

Vérifier que l’interface artiste s’affiche.

Vérifier que les outils ADMIN sont absents.

TEST C — DANSEUR

Créer/ouvrir un espace danseur.

Vérifier que l’espace adapté au profil apparaît.

Vérifier que les outils ADMIN sont absents.

TEST D — AUTRE ACTIVITÉ

Tester au moins une autre activité, par exemple :

🎥 Vidéaste

ou

🎚️ Producteur.

Vérifier que l’espace reste adapté au profil.

TEST E — ADMIN

Se connecter avec le compte ADMIN autorisé.

Vérifier que le Centre de pilotage ADMIN est accessible.

TEST F — SÉCURITÉ

Avec un compte non ADMIN :

tenter d’accéder directement à une URL ADMIN.

Résultat attendu :

🔐 accès refusé.

Avec un compte visiteur :

tenter d’accéder à une fonction artiste protégée.

Résultat attendu :

🔐 accès refusé.
