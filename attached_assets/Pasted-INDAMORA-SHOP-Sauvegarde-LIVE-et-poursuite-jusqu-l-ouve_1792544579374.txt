1. Sauvegarde et retour arrière

* Identifie une méthode réellement disponible avec le plan Replit actuel et les accès existants, sans achat ni changement de forfait.
* Vérifie si un export PostgreSQL complet ou ciblé sur les données Shop est possible.
* Protège la sauvegarde : aucun secret dans les fichiers, aucun dépôt Git, aucune sauvegarde publique ou non chiffrée dans un espace partagé.
* Teste la restauration dans une base PostgreSQL isolée, sans modifier la production.
* Vérifie l’intégrité des données restaurées et documente la procédure de retour arrière.
* Détermine séparément si une restauration vers la base Replit de production est possible avec les droits disponibles.
* Si l’accès SQL est en lecture seule, cherche une méthode autorisée utilisant les outils ou permissions déjà disponibles. Ne contourne pas les restrictions.

Ne prétends pas qu’une sauvegarde est restaurable si le test de restauration n’a pas réussi. Si une étape est impossible, explique précisément pourquoi et indique l’action minimale requise.

Ne suspends pas toutes les tâches pendant la recherche de sauvegarde.
